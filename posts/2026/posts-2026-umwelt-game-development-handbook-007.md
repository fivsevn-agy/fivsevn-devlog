你在 [UMWELT](https://umwelt.fivsevn.com/) 中使用自然史和人文资料时，会经历几次转换：先理解来源支持什么，再决定保留哪些内容，随后把它们安排为画面、操作和反馈。玩家接触到的是经过这些取舍的作品，因此还需要检查，他们会怎样理解其中的事实与创作。

本篇沿着这条关系整理制作方法。把每一步的依据与决定记录下来，就能在以后扩展或修订资料时，找到需要调整的说明、资源和规则。

<a id="layers"></a>
## 1｜区分资料、设计与游戏结果

| 层次 | 内容 | 与下一层的关系 |
| --- | --- | --- |
| 资料陈述 | 来源在明确对象与条件下支持的信息 | 为设计提供依据，同时保留适用范围 |
| 设计解释 | 作者为表达与制作作出的理解和取舍 | 决定哪些关系进入作品，哪些需要简化 |
| 游戏规则 | 程序实际执行的条件、状态与结果 | 使玩家能够行动，并得到对应反馈 |
| 玩家理解 | 玩家根据内容与操作形成的解释 | 通过试玩观察，再用于修改设计或说明 |

例如，一项研究可能记录了特定条件下的动物反应。为了便于观察，游戏可以压缩反应时间或强化可见差异；这些变化服务于体验，却也会改变玩家看到的尺度。因此，记录时应同时保留原始条件和游戏采用的处理方式，使读者能够分清两者。

**资料提供依据，设计作出取舍，程序执行规则，试玩检验表达效果。** 沿着这四步记录，比在作品末尾集中写一句笼统的“仅供参考”更容易解释具体内容。

<a id="evidence"></a>
## 2｜来源核查与证据范围

资料的可靠性需要结合正在支持的陈述判断。原始研究可以说明具体观察，综述帮助理解研究背景，数据库整理名称与记录，访谈则保留当事人的经验。它们各有用途，核查时应先确认问题，再选择合适的来源。[1](#ref-1)

| 资料类型 | 可以支持的内容 | 核查重点 |
| --- | --- | --- |
| 原始研究 | 特定方法和条件下的结果 | 样本、对象、设置与适用范围 |
| 综述或教材 | 背景知识与主要研究观点 | 出版时间、概括层次与争议处理 |
| 分类和生物多样性数据库 | 名称、分布记录和来源关系 | 数据版本、鉴定信息与采样范围 |
| 历史档案 | 当时形成的记载和表达 | 记录者立场、保存过程与缺失 |
| 口述、访谈与参与式资料 | 当事人的经验和解释 | 同意、语境、代表范围与合作关系 |
| 图像和视频 | 可见形态、空间与动作参考 | 拍摄条件、编辑处理和使用许可 |
| 开发者记录 | 制作过程与设计意图 | 发表时间、具体版本与作者参与的范围 |

同一段文字可能被多个网站转载，因此来源数量还要与独立性一起判断。摘要也会省略方法和限制；当某项结论将直接影响设计时，应继续读到足以确认适用条件的部分。

**[《Pentiment》](https://pentiment.obsidian.net/)的历史顾问参与了这样的细节工作。** Lawrence University 的记录说明，Josh Sawyer 邀请 Edmund Kern 和 Winston Black 参与咨询，通过资料与讨论帮助处理游戏中的早期近代欧洲背景。[8](#ref-8) 对研究型制作而言，这说明核查可以持续伴随设计：当场景或人物行动出现具体问题，再请熟悉该领域的人检查其条件，而不是只在项目开始时收集一份书单。

最小来源记录可以包含作者或机构、题名、日期、链接或 DOI、支持的陈述、适用条件、查阅位置和使用限制。**文献条目帮助找到资料，陈述与来源的对应关系则说明引用它的理由。**

<a id="translation"></a>
## 3｜把资料转化为玩家行为

资料进入游戏时，可以影响玩家需要注意什么、能够采取什么行动，以及行动会造成什么变化。这些关系决定了研究怎样成为体验。

**[《Walden, a game》](https://www.waldengame.com/)将文学主题转化为日常活动。** 官方介绍说明，玩家需要处理食物、燃料、住所与衣物，同时探索自然环境。游戏借这些活动组织对生活和环境的注意，而不只是把原著内容放进文字窗口。[4](#ref-4) 从设计角度看，改编因此也发生在时间分配和行动取舍上。

回到你的观察游戏，可以用下面的流程整理一项内容（表中的动物反应是假设性示例，实际制作时要替换为已核对的物种、来源与条件）。

| 转化环节 | 演示内容 |
| --- | --- |
| 资料陈述 | 在特定条件下，记录到一种回避反应 |
| 边界记录 | 明确对象、刺激、观察方法与不确定部分 |
| 设计选择 | 保留“干预改变观察条件”的关系 |
| 玩家行为 | 调整观察距离，或暂时停止干预 |
| 游戏反馈 | 通过姿态、活动或线索呈现条件变化 |
| 创作说明 | 解释哪些时长、强度或形态经过调整 |
| 验证 | 检查玩家能否区分游戏表现与真实测量结果 |

一份资料也可以帮助你决定暂缓某种表现。例如，对象身份尚未确定时，可以保留暂定标记；缺少某项行为依据时，可以改用更有限的观察描述。研究由此参与了内容的增加，也参与了范围的收缩。

关于规则怎样表达观点，Bogost 的“程序修辞”提供了一种分析视角。[2](#ref-2) 你可以据此检查：游戏允许什么、限制什么、鼓励什么，这些安排共同呈现了怎样的关系。理论帮助提出问题，具体事实仍由对应资料支持。

<a id="uncertainty"></a>
## 4｜简化、拟人化与不确定性

游戏需要在有限时间和显示空间中组织体验，因此经常会压缩过程、放大差异或合并信息。关键在于说明处理发生在哪里，以及它是否改变了读者对事实的理解。

| 处理方式 | 可以怎样交代 |
| --- | --- |
| 时间压缩 | 标明游戏时长与真实过程之间的关系 |
| 视觉夸张 | 说明比例、颜色或动作幅度怎样服务于辨认 |
| 合并对象 | 说明采用综合形象还是具体对象的复原 |
| 暂定判断 | 保留不同来源和当前采用解释的理由 |
| 拟人化叙事 | 区分角色语言、作者表达和动物研究陈述 |
| 虚构情境 | 标出为故事新设的关系，并与真实术语分开说明 |

信息不足时，也可以把这种状态留在作品中。例如允许玩家暂缓判断，或者展示几个都有根据的解释。要让这种安排成立，界面仍需说明已知条件与可用行动，使玩家理解自己在面对什么样的不确定性。

你使用的 Umwelt 概念也有类似的分工。Uexküll 的著作为作品提供思想背景，关于具体物种的形态和行为则需要相应研究资料。[3](#ref-3), [6](#ref-6) 因此，思想来源与实证来源最好分别引用：前者解释你从什么角度观察，后者支持你对某种现象作出的陈述。

<a id="cases"></a>
## 5｜把文化合作纳入制作流程

涉及仍在生活和传承的文化时，资料还关联着讲述者、使用语境和合作关系。创作者需要考虑谁参与解释、怎样记录意见，以及如何处理不同理解。

**[《Never Alone》](https://www.neveralonegame.com/never-alone)把这种合作放进了制作过程。** 官方说明列出 Iñupiat 社群成员、长者和讲述者的参与，作品也提供由相关成员讲述的文化访谈。[5](#ref-5) 这里，文化资料既成为游戏内容，也通过参与者的声音保留了讲述背景。

据此，你可以在类似项目中安排资料访谈、翻译、审阅和署名，并为参与者投入的工作明确报酬或合作条件。一位参与者提供的是其自身经验和判断；若作品需要概括更广的群体，就应继续比较其他材料和观点。

因此，文化合作需要时间与沟通安排。提前把这些工作列入制作计划，才有机会在设计仍可修改时处理分歧，而不把全部意见留到完成后的介绍文字中。

<a id="umwelt"></a>
## 6｜对照你的 UMWELT 与两个实验室

你已经在项目说明中区分资料事实、研究参考、工作性判断、视觉参数、交互参数与虚构内容。[6](#ref-6) 形态实验室和环境实验室进一步提供了合适的资料位置：物种资料对应标本，环境资料对应具体生境，游戏则把选定信息组织成观察和交互。[7](#ref-7)

| 位置 | 应承担的职责 |
| --- | --- |
| 共享来源记录 | 保存来源身份和可查入口 |
| 物种资料 | 说明来源支持哪些分类、形态或行为信息 |
| 环境资料 | 说明来源支持哪些空间与环境过程 |
| 游戏内容 | 把选定关系转化为观察、行动和反馈 |
| 创作与维护记录 | 保存简化、虚构、修订和待解决的问题 |

这样，玩家可以先在游戏里观察，需要了解背景时再进入实验室。游戏界面保持简洁，资料则继续留在可以追溯的位置，两项目标可以同时满足。

以后新增一种鼠妇或生境时，可以依次确认需要支持的陈述、来源条件、设计处理和接入位置，再检查资料与游戏表现的对应。若来源后来修订，还要判断影响停留在说明文字，还是已经涉及视觉参数、规则或旧进度的解释。

事实核查检查陈述与来源的关系，游戏测试检查程序与预期行为的关系。因为两者验证的对象不同，所以应分别记录结果，再共同用于内容验收。

<a id="cost"></a>
## 7｜研究工具、资料平台与成本

资料可以通过软件整理，也可以通过数据库、图书馆和出版社获取。获取方式与再使用条件各有规定，因此预算中需要把软件、文献、素材和研究工作分别考虑（费用形式记录日期：2026-10-13）。

| 工具或资源 | 开放情况 | 费用与用途 |
| --- | --- | --- |
| [Zotero](https://www.zotero.org/) | 开源软件 | 本地管理免费，[附件云存储扩容](https://www.zotero.org/storage)有付费方案 |
| [Obsidian](https://obsidian.md/pricing) | 专有软件 | 本地应用免费，Sync、Publish 等可选服务付费 |
| [LibreOffice Calc](https://www.libreoffice.org/) | 开源 | 软件免费，可整理来源和参数清单 |
| [draw.io](https://www.drawio.com/) | 开源核心 | 核心免费，部分集成付费，可绘制资料与设计关系 |
| [GBIF](https://www.gbif.org/) | 公共生物多样性数据基础设施 | 按平台方式获取数据，具体许可、来源与敏感记录条件另看 |
| [WoRMS](https://www.marinespecies.org/) | 海洋生物分类资料平台 | 公开查询，引用与数据使用按平台说明 |
| [Crossref](https://www.crossref.org/) | 文献标识与元数据基础设施 | 辅助核对 DOI 和出版信息，全文获取由出版渠道决定 |
| 出版社与图书馆 | 文献获取渠道 | 开放获取、购买或机构借阅，引用与再分发按资料条件处理 |

研究预算还包括核查时间、翻译、专业咨询和文化合作。软件可以减少整理工作，但这些判断仍需要有人完成。因此，比较成本时，应同时确认能够取得什么材料，以及谁负责读懂并检查它们。

AI 可以辅助拟定检索词、整理格式和比对文本。由于生成内容可能出现错误，书目和事实仍需回到真实资料核对，再将实际查到的来源写入参考文献。

## 参考文献与学习资源

下面分别提供研究方法、表达理论、思想背景和创作者案例。按资料承担的角色阅读，更容易把它们放回自己的制作过程（网页查阅日期：2026-10-13；自己的项目资料固定到提交 `0bbe083`）。
