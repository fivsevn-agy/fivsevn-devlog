有了题材，还需要决定玩家怎样参与其中。以你的观察游戏为例，“人与动物的关系”可以提供主题，观察、接近和等待则成为玩家的行为；这些行为得到怎样的回应，又会影响玩家对关系的理解。因此，玩法设计需要把主题、操作、规则和反馈连接起来，再通过试玩检查这种安排能否形成预期体验。[1](#ref-1), [2](#ref-2)

具体程序可以由开发者实现，但希望玩家做什么、知道什么和感受到什么，仍需在设计中说明。本篇围绕这些决定展开。战斗、升级和奖励可以是其中一种组织方式，探索、观察与对话也各有适合自己的结构。

<a id="experience"></a>
## 1｜从体验目标到玩家行为

“温柔”“紧张”“哲学性”可以帮助确定方向。为了继续制作，还需要把这些词展开：玩家在什么情境下采取什么行动，游戏通过哪些变化回应他。这样，抽象目标才有了可以尝试和调整的形式。

| 体验方向 | 可以安排的行为 | 试玩时可以观察的内容 |
| --- | --- | --- |
| 谨慎观察 | 干预前改变观察位置、比较线索 | 玩家是否愿意先观察，再采取行动 |
| 照料与责任 | 选择投入对象，并承受取舍 | 玩家是否理解资源有限，需要作出决定 |
| 不确定性 | 根据不完整资料形成暂时判断 | 玩家能否理解信息为何不足，以及还有哪些探索途径 |
| 亲近或疏离 | 接近、等待、回应或离开 | 角色反应是否使关系变化可以被察觉 |

这些是设计假设。不同玩家可能产生不同理解，所以需要记录他们的实际行为，再判断安排是否有效。例如，你希望等待体现耐心，但玩家可能只觉得系统没有回应；此时要检查的是等待过程中的信息与变化，而不能仅凭原先的创作意图判定设计已经成立。

《Game Design Workshop》将体验目标、原型和试玩连接起来；《The Art of Game Design》则提供从不同角度检查设计的方法。[1](#ref-1), [2](#ref-2) 你可以借助它们把想法拆开，并在每次修改后重新观察结果。

<a id="rules"></a>
## 2｜操作、规则、信息与反馈

| 概念 | 解释 | 需要安排的内容 |
| --- | --- | --- |
| 操作 | 玩家实际实施的动作 | 点击、移动、等待、选择或组合 |
| 规则 | 操作在什么条件下造成什么结果 | 接近是否打断行为，等待是否推进时间 |
| 信息 | 玩家作决定时能够获得的内容 | 当前目标、可用行动、线索和风险 |
| 反馈 | 游戏呈现结果的方式 | 文字、姿态、声音、环境与界面变化 |
| 核心循环 | 反复出现的行为与反馈关系 | 例如观察 → 判断 → 行动 → 新的观察 |

循环的内容由作品目标决定。动作游戏可以围绕挑战与重试组织，探索游戏可以围绕线索与调查组织；你的作品则可以让玩家反复比较环境、暂缓判断，再继续观察。

**《Undertale》把态度落实为可执行的选择。** 玩家既可以战斗和躲避攻击，也可以交涉并避免杀戮。[3](#ref-3) 从设计角度看，这使“如何对待对方”进入了操作和规则。把这个关系放回你的作品，也可以继续考虑：角色表达的观点，是否有相应行动让玩家回应，而不仅通过台词接受信息。

信息的不完整也需要区分用途。作品可以有意隐藏答案，让玩家通过线索形成判断；但操作界面仍应说明当前能做什么。前者保留探索空间，后者帮助玩家参与探索，两者需要同时安排。

<a id="choices"></a>
## 3｜选择的不同职责

选择可以改变事件，也可以表达态度、决定调查方向或安排顺序。明确每个选项的作用后，就能选择合适的反馈方式，并估算后续内容量。[4](#ref-4)

| 选择类型 | 主要作用 | 制作时需要检查 |
| --- | --- | --- |
| 行为选择 | 决定采取什么行动 | 文本描述与实际执行是否一致 |
| 信息选择 | 决定观察或追问什么 | 关键线索和补充材料怎样区分 |
| 态度选择 | 表达立场或关系 | 后续回应能否承接这种态度 |
| 资源选择 | 分配时间、物品或机会 | 玩家获得了哪些判断成本与后果的依据 |
| 顺序选择 | 决定事情发生的先后 | 先后变化怎样影响理解或体验 |
| 分支选择 | 改变后续事件或路径 | 分歧、汇合和验证范围怎样组织 |

**《Heaven’s Vault》将调查与解释联系起来。** 玩家通过线索尝试理解一种古代语言，形成的解释会参与后续探索，故事也随所走路径调整。[8](#ref-8) 这个案例适合说明信息选择：玩家选择的既是前往哪里，也是如何理解已经发现的材料。

分支会增加内容与检查工作，因此应先确定哪些差异值得持续保留。作为一个结构示例，三次选择每次分成三条互不汇合的路线，会产生 27 种选择组合；若部分路线后来汇合，就可以共享场景，同时用此前记录调整回应。

这里，**分支组织不同路径，状态记录已经发生的事。** 即使两条路径回到同一个地点，人物仍可以根据此前的选择说出不同内容。因而，是否保留独立场景，应由表达需求决定，而不是只用结局数量衡量选择的价值。

<a id="narrative"></a>
## 4｜故事文本与交互叙事

对白和事件提供故事材料。玩家能够选择和行动后，内容的出现顺序还会受到条件与状态影响，因此交互叙事需要同时规定内容何时进入、怎样推进、如何结束，以及中断后从哪里恢复。[4](#ref-4)

| 项目 | 需要记录的内容 |
| --- | --- |
| 情境 | 地点、人物与当前问题 |
| 进入条件 | 此前需要完成哪些事 |
| 已知信息 | 玩家到这里时应当已经知道什么 |
| 可用行动 | 当前能做什么，哪些行为需要等待条件满足 |
| 结果 | 行动改变哪些状态或后续内容 |
| 表现 | 台词、姿态、声音和场景怎样变化 |
| 恢复方式 | 返回、重载或中断后从哪里继续 |

**《Outer Wilds》用叙事支持好奇心驱动的探索。** 编剧 Kelsey Beachum 在演讲中介绍了非线性故事怎样帮助玩家形成调查目标。[5](#ref-5) 玩家可以自行决定下一步，但游戏仍要提供能够引起注意并相互关联的线索。由此可以看出，自由探索的引导方式可以更含蓄，却仍然需要经过设计（演讲涉及作品内容，可能包含剧透）。

对你希望隐藏在对话中的故事，也可以采用相同的检查方式：先明确玩家此时掌握了哪些线索，再安排新信息与旧信息的联系。这样，后来的理解来自逐步积累，而不是作者突然补出一个此前无从判断的结论。

<a id="pacing"></a>
## 5｜节奏、学习、失败与等待

玩家的体验由操作、阅读、观察、移动、等待和重试共同组成。每种活动占用不同的注意力，所以需要根据场景目标安排它们的交替。例如，连续得到新信息之后，可以留出观察或回看机会，帮助玩家整理已经发生的事。

| 安排 | 设计重点 |
| --- | --- |
| 引入操作 | 让玩家认出可以做什么，并及时看到结果 |
| 增加变化 | 在理解基础行为后，改变条件或组合已有行为 |
| 设置失败 | 让失败提供可用信息，并安排合适的重试成本 |
| 留出停顿 | 提供理解、观看和情绪转换的时间 |
| 提供辅助 | 允许调整阅读速度、动作强度或输入方式 |

**《Celeste》说明，操作宽容度与关卡挑战可以分别设计。** 开发者介绍的“离开平台后仍保留短暂起跳机会”等处理，使稍有误差的输入仍能表达玩家意图。[9](#ref-9) 设计上由此可以把挑战更多放在判断与路线安排，而减少由细小输入误差造成的挫折。讨论难度时，应先明确希望挑战哪种能力，再调整相应条件。

等待也需要有参与方式。若等待是有效选择，应明确这期间环境怎样变化、玩家能观察什么，以及是否可以中断。若等待只是资源加载，则需要提示进度或状态，使玩家理解接下来应等待还是操作。

Maddy Thorson 关于《Celeste》的关卡演讲还讨论了局部关卡与区域组织。[6](#ref-6) 你可以把它作为观察尺度变化的材料：一个操作片段的节奏，需要与整段体验的强弱安排联系起来。

<a id="validation"></a>
## 6｜从设计说明到试玩验证

设计文档记录你希望发生的体验，试玩记录玩家实际经历了什么。两份记录出现差异时，可以先找到差异发生的环节，再决定修改信息、规则还是反馈。[1](#ref-1)

| 观察到的情况 | 可以先检查的部分 |
| --- | --- |
| 玩家不知道能操作哪里 | 对象辨识、引导与输入反馈 |
| 玩家理解操作，但不愿继续 | 行为价值、变化、节奏和题材吸引力 |
| 玩家作出选择，却认为没有生效 | 状态变化与可见反馈的联系 |
| 玩家得到结果，却不了解原因 | 条件信息、因果提示和规则一致性 |
| 玩家走完分支，却觉得人物反应断裂 | 前置记录、条件组合和人物上下文 |

测试者的经验与偏好可能不同，因此应记录他们的背景和具体行为，再判断反馈适用于什么范围。试玩时也应尽量让界面自己传达信息；如果需要你不断在旁解释，就应把这些解释记下来，判断是否需要进入正式设计。

每一轮可以保留设计原意、实际观察和下一项变更。修改因素越明确，就越容易比较前后结果。自动化适合重复检查路径是否可达、记录是否保存；体验目标则还需要通过实际参与来观察。因此，两类验证应互相补充。

<a id="isopoda"></a>
## 7｜回到你正在做的《等足目赋格》

你的游戏将内容、环境、状态和交互分开维护，部分直接操作会进入观察记录，并参与后续反馈。[7](#ref-7) 这使叙事有了两种相连的表达方式：文字说明观察到了什么，操作与回应则让玩家参与观察过程。

以后继续增加内容时，可以先按下面的关系整理一个片段（以下是设计演示，具体生物行为另需核对资料）。

| 设计层次 | 示例 |
| --- | --- |
| 主题 | 观察方式会影响观察情境 |
| 行动 | 接近、保持距离、暂时离开 |
| 状态 | 记录干预方式与观察到的现象 |
| 反馈 | 不同条件使某些细节更容易或更难看见 |
| 叙事 | 后续文字承接玩家改变过条件的经历 |
| 验证 | 玩家能否把信息差异与自己的观察方式联系起来 |

主题由此转化为具体的设计约束。关于真实动物的陈述，再按 [007](posts-2026-umwelt-game-development-handbook-007.html) 追溯来源，使资料依据与创作选择都能查到。

**[9] Thorson, Maddy. _Celeste & Forgiveness_.** [作者文章](https://www.maddymakesgames.com/articles/celeste_and_forgiveness/index.html)。英文，免费，附动作演示。适合与关卡演讲一起阅读，区分操作响应与挑战设计。

**公开课程：Tan, Philip B.；Begy, Jason. _Game Design_, MIT CMS.608（2010 秋）.** [MIT OpenCourseWare](https://ocw.mit.edu/courses/cms-608-game-design-fall-2010/)。英文，课程资料、录音与项目示例免费。课程通过非数字游戏分析和测试规则；可以先看第 3 讲的设计方法、第 9 讲的信息与不确定性，以及第 25 讲的故事内容。

**工具配套资源：inkle，ink 基础教程与作者手册。** [官方入口](https://www.inklestudios.com/ink/)。英文，基础网页教程免费，出版物另计。先了解文字和条件怎样组织，再由具体开发者处理实现。
