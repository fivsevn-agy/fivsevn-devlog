题材说明作品涉及什么，玩法规定玩家能够怎样参与，叙事组织信息、事件和人物关系。三者可以相互支持，但不能互相替代。设计的起点可以是一段故事、一种操作或一个研究问题；最终都需要在实际游玩中检验。[1](#ref-1)[2](#ref-2)

本篇主要讨论项目负责人需要确定的体验与规则，不要求编写程序，也不把所有作品都套进战斗、升级和奖励的模式。

<a id="experience"></a>
## 1｜从体验目标到玩家行为

“温柔”“紧张”“哲学性”“沉浸感”可以作为方向，但还不足以交给实现者。需要继续说明玩家在什么情况下进行什么行为，以及预期通过哪些结果形成这种感受。

以下为设计说明示例，不是已验证的普遍效果：

| 体验方向 | 可安排的行为 | 可以观察的反馈 |
| --- | --- | --- |
| 谨慎观察 | 在干预前改变观察位置、比较线索 | 玩家是否愿意先看，再采取行动 |
| 照料与责任 | 选择投入对象，并承受取舍 | 玩家是否理解自己不能同时满足所有需求 |
| 不确定性 | 根据不完整资料作出暂时判断 | 玩家能否区分证据不足与界面说明不清 |
| 亲近或疏离 | 决定接近、等待、回应或离开 | 角色反应是否让玩家察觉关系变化 |

这种对应不是承诺玩家必然产生某种情绪，而是把创作意图转为可试验的安排。**体验目标描述希望形成的感受，行为与规则构成实现条件，试玩用于检查实际结果。**

《Game Design Workshop》强调围绕玩家体验进行原型、测试和迭代；《The Art of Game Design》则提供从不同角度检查设计的“透镜”。它们是辅助分析的方法，不是可以机械套用的成功公式。[1](#ref-1)[2](#ref-2)

<a id="rules"></a>
## 2｜操作、规则、信息与反馈

| 概念 | 解释 | 示例性判断 |
| --- | --- | --- |
| 操作 | 玩家实际实施的动作 | 点击、移动、等待、选择、组合 |
| 规则 | 操作在什么条件下造成什么结果 | 接近是否打断行为，等待是否改变环境 |
| 信息 | 玩家作决定时能够获得的内容 | 是否知道当前目标、风险和可用行动 |
| 反馈 | 游戏呈现结果的方式 | 文字、姿态、声音、环境或菜单变化 |
| 核心循环 | 反复出现的行为与反馈关系 | 观察 → 判断 → 行动 → 新的观察 |

循环并不一定意味着刷取奖励。探索可以循环于“发现线索—形成解释—前往新地点”，观察作品也可以循环于“比较—暂缓判断—继续观察”。

**《Undertale》案例。** 官方作品介绍同时列出战斗、实时躲避，以及通过交涉避免杀戮的方式。[3](#ref-3) 本文据此作出的设计分析是：态度可以体现为可执行的行动，而不只是一句对白。它说明主题与规则可以连接，并不意味着所有叙事游戏都需要道德分数或善恶结局。

信息不足也有两种情况：一是设计希望保留不确定性，二是玩家不知道按钮会做什么。前者可以产生探索，后者可能只是沟通失败。设计时应分别检查。

<a id="choices"></a>
## 3｜选择的不同职责

不是每个选项都必须生成独立结局，但选项的作用应与玩家预期一致。选择可以改变事件，也可以表达态度、分配注意力或安排顺序。[4](#ref-4)

| 选择类型 | 主要作用 | 常见风险 |
| --- | --- | --- |
| 行为选择 | 决定采取什么行动 | 文字说一件事，执行却发生另一件事 |
| 信息选择 | 决定观察或追问什么 | 没有区分关键线索与补充资料 |
| 态度选择 | 表达立场或人物关系 | 承诺明显不同的态度，却没有任何可感知回应 |
| 资源选择 | 分配时间、物品或机会 | 成本和后果完全不可判断 |
| 顺序选择 | 决定先后，不一定改变终点 | 先后关系没有产生任何体验差异 |
| 分支选择 | 改变后续事件或路径 | 内容规模扩大，却没有安排汇合与测试 |

分支数量不是叙事质量的指标。若三次选择每次都分成三条完全独立、永不汇合的路线，理论上会出现 27 条组合路径；如果使用汇合、条件化回应或共享场景，实际内容量可以不同。这里是结构演示，不是任何游戏的真实制作统计。

**分支记录路线差异，状态保存此前发生的事。** 两条路线可以回到同一个场景，但角色根据既有记录作出不同回应。因此，汇合并不自动等于选择没有影响。

<a id="narrative"></a>
## 4｜故事文本与交互叙事

剧情文本描述台词与事件，交互叙事还要规定进入条件、可用行动、退出条件以及此前记录的影响。写完对话不等于完成叙事设计。[4](#ref-4)

一段内容可以用以下结构交付，不必先选择脚本语言：

| 项目 | 需要记录的内容 |
| --- | --- |
| 情境 | 地点、人物与当前问题 |
| 进入条件 | 玩家此前需要完成哪些事 |
| 已知信息 | 玩家在此时应该知道什么 |
| 可用行动 | 能做什么，哪些操作暂不可用 |
| 结果 | 行动改变哪些状态或后续内容 |
| 表现 | 台词、姿态、声音与场景变化 |
| 恢复方式 | 中断、重载或返回后从哪里继续 |

**《Outer Wilds》案例。** 编剧 Kelsey Beachum 的演讲说明了以好奇心驱动探索、通过非线性故事组织开放世界的设计目标。[5](#ref-5) 这个案例适合观察线索如何引导行动，而不是将“没有任务清单”当作可以省略引导的理由。

本系列采用的设计判断是：没有显眼指令时，地点、线索与反馈仍需形成可以理解的联系。**叙事不仅负责告诉玩家发生了什么，也可以负责使玩家产生下一步行动的理由。**

<a id="pacing"></a>
## 5｜节奏、学习、失败与等待

节奏由操作、阅读、观察、移动、等待与重试共同形成。文字少不一定节奏快，动作多也不一定参与感强。需要结合场景目标安排强度变化。

**《Celeste》案例。** 设计者在 GDC 2017 的演讲中讨论了关卡制作过程、区域组织及故事在世界中的编排。[6](#ref-6) 对本系列而言，值得借鉴的是将局部操作与整段体验一起考虑；演讲涉及的是当时的制作经验，不代表所有关卡都必须遵循同一个模板。

| 安排 | 设计重点 |
| --- | --- |
| 引入一种操作 | 先让玩家知道能够做什么，并看到结果 |
| 增加变化 | 改变条件或组合已有行为，而不是只增加说明文字 |
| 设置失败 | 明确失败提供什么信息，以及重试成本是否合适 |
| 安排停顿 | 留出理解、观看或情绪转换的时间 |
| 提供辅助 | 允许调整阅读速度、动作强度或输入方式，不把障碍误当挑战 |

等待需要可理解的边界。若等待是一个有效选择，应说明时间是否推进、环境是否变化，以及玩家能否中断。若只是技术加载，应明确提示而不是包装成谜题。

难度也要区分理解、操作、记忆、资源与信息压力。缩短反应时间与加深思考难度不是同一件事；提高某个数值不能自动得到更好的挑战。

<a id="validation"></a>
## 6｜从设计说明到试玩验证

设计文档记录意图，试玩记录实际行为。两者出现差异时，应先判断原因，而不是立即增加提示或删除系统。[1](#ref-1)

| 观察到的情况 | 可能需要检查的部分 |
| --- | --- |
| 玩家不知道能操作哪里 | 可操作对象的辨识、引导与输入反馈 |
| 玩家理解操作，但不愿继续 | 行为价值、变化、节奏或题材吸引力 |
| 玩家选了某项，却认为没有生效 | 反馈与状态变化之间的联系 |
| 玩家得到结果，却不知道原因 | 条件信息、因果提示与规则一致性 |
| 分支能运行，但人物反应不连贯 | 前置记录、条件组合与叙事上下文 |

不要把一名测试者的意见直接当成所有玩家的结论，也不要把设计者在旁边不断解释后的完成，视为界面已经能够独立传达信息。

本系列建议保留三类记录：设计原意、实际观察、下一轮变更。一次只改变有限因素，更容易判断变化来自哪里。自动化检查可以确认分支可达或存档一致，却不能单独证明情绪、节奏或表达已经成立。

<a id="isopoda"></a>
## 7｜《等足目赋格》的实际对应与设计练习

已核对的《等足目赋格》将内容、状态、环境、交互和语言显示分开维护，部分直接操作会进入观察记录并影响反馈。[7](#ref-7) 因此，项目中的叙事不只存在于文本文件，也存在于操作与反馈的关系中。

以下为可用于后续讨论的**演示性设计**，不是声称游戏已经包含这一段：

| 设计层次 | 示例 |
| --- | --- |
| 主题 | 观察会影响被观察的情境 |
| 行动 | 接近、保持距离、暂时离开 |
| 状态 | 记录干预方式与观察到的现象 |
| 反馈 | 同一现象在不同条件下呈现不同细节 |
| 叙事 | 后续文字承认玩家改变过条件，而不是给出唯一正确解释 |
| 验证 | 玩家能否理解信息受观察方式影响，而非以为程序随机出错 |

主题在这里形成对设计的约束，但不替代具体规则。关于真实动物行为的陈述，还必须按 [007](posts-2026-umwelt-game-development-handbook-007.html) 的来源方法核对。

### 本篇工具与费用

标注日期：**2026-10-13**。这些是可选的组织工具，不是要求现有项目迁移。

| 工具 | 开放情况 | 费用与职责 |
| --- | --- | --- |
| [Twine](https://twinery.org/) | 开源 | 软件免费，用于文本段落和分支组织；故事格式及附加资源另看许可 |
| [ink／Inky](https://www.inklestudios.com/ink/) | 开源，MIT | 软件免费；语言与编辑器分别负责叙事表达和编写测试 |
| [Ren’Py](https://www.renpy.org/) | 开源 | 引擎免费，包含商业使用；素材及附加组件单独核对 |
| [Yarn Spinner](https://www.yarnspinner.dev/) | 开源核心与商业产品并存 | 核心可免费使用；Pro、支持和附加工具按产品收费 |
| [articy:draft](https://www.articy.com/en/) | 专有软件 | 免费／受限方案与付费许可按版本区分，协作能力需另核对 |
| [draw.io](https://www.drawio.com/) | 开源核心 | 网页／桌面核心免费；部分平台集成收费，可用于流程图 |

工具可以帮助检查结构，但不能替代选择的意义、人物一致性和节奏判断。分支增加后，还要计算翻译、配音、美术、存档与测试的连带成本。

## 参考文献与学习资源

这里包括游戏设计教材、大学公开课程和实际开发者演讲，不以 AI 生成内容作为依据。资源的“优先阅读”是本系列针对非程序岗位的建议，不是行业统一必修清单。网页查阅日期：**2026-10-13**。

<a id="ref-1"></a>
**[1] Fullerton, Tracy. _Game Design Workshop: A Playcentric Approach to Creating Innovative Games_，第 5 版（2024）.** [出版社与目录](https://www.routledge.com/Game-Design-Workshop-A-Playcentric-Approach-to-Creating-Innovative-Games/Fullerton/p/book/9781032607009)。书籍付费或借阅，目录免费，英文。**优先教材**：阅读玩家体验、原型、试玩和迭代部分；不要求先具备程序或美术制作能力。

<a id="ref-2"></a>
**[2] Schell, Jesse. _The Art of Game Design: A Book of Lenses_，第 3 版.** [出版社入口](https://www.routledge.com/The-Art-of-Game-Design-A-Book-of-Lenses-Third-Edition/Schell/p/book/9781315208435)。书籍付费或借阅，英文。用作设计检查参考，优先看体验、规则、界面与故事相关部分，不必一次使用全部“透镜”。

<a id="ref-3"></a>
**[3] GameMaker／Toby Fox. _Undertale_.** [官方作品展示](https://gamemaker.io/en/showcase/undertale)。免费网页，英文。用于核对行动方式与作品信息，不将商店介绍当作完整的内部设计文档。

<a id="ref-4"></a>
**[4] Heussner, Tobias；Finley, Toiya Kristen；Hepler, Jennifer Brandes；Lemay, Ann. _The Game Narrative Toolbox_，第 2 版.** [出版社与目录](https://www.routledge.com/The-Game-Narrative-Toolbox/Heussner-Finley-BrandesHepler-Lemay/p/book/9781032438962)。书籍付费或借阅，英文。重点看叙事设计职责、故事实现、对白和制作问题，适合区分写故事与设计交互叙事。

<a id="ref-5"></a>
**[5] Beachum, Kelsey. _Independent Games Summit: Sparking Curiosity-Driven Exploration Through Narrative in Outer Wilds_. GDC 2021.** [演讲入口](https://www.gdcvault.com/play/1027368/Independent-Games-Summit-Sparking-Curiosity)。该条目标为免费内容，英文视频。重点看叙事如何支持好奇心与行动动机；包含作品内容讨论，介意剧透时可先体验游戏。

<a id="ref-6"></a>
**[6] Thorson, M. _Level Design Workshop: Designing Celeste_. GDC 2017.** [演讲入口](https://www.gdcvault.com/play/1024307/Level-Design-Workshop-Designing-Celeste)。该条目标为免费内容，英文视频。重点看局部关卡、区域结构和叙事编排的关系，不是某个关卡编辑器的操作课程。

<a id="ref-7"></a>
**[7] fivsevn. UMWELT：ISOPODA 模块与叙事状态实现.** [模块说明](https://github.com/fivsevn/umwelt/blob/0bbe083943a4b307e38e3ea0de435d3d7864a345/isopoda/README.md) · [交互记录与规则](https://github.com/fivsevn/umwelt/blob/0bbe083943a4b307e38e3ea0de435d3d7864a345/isopoda/engine.mjs)。免费查看，固定版本用于实际案例，不要求读代码。

**公开课程：Tan, Philip B.；Begy, Jason. _Game Design_, MIT CMS.608（2010 秋）.** [MIT OpenCourseWare](https://ocw.mit.edu/courses/cms-608-game-design-fall-2010/)。免费课程资料、课堂媒体与项目示例，英文。课程以非数字游戏的设计和测试为重要内容，适合先理解规则如何影响体验；旧课程不是当前软件版本教程。

**工具配套资源：inkle，ink 基础教程与作者手册。** [官方入口](https://www.inklestudios.com/ink/)。免费网页教程，另有付费出版物。了解文本与条件的组织方式即可，具体脚本实现可以继续由开发者完成。

**建议顺序：** 先看 MIT 课程的规则与试玩材料，再选 [1] 作为系统教材；需要叙事深化时看 [4]、[5]，需要关卡组织时看 [6]。
