# Intake

`intake/` generates the [public daily intake page](https://devlog.fivsevn.com/intake/).

The page is an information-source library with three parts:

- a daily postcard
- a Daily Field Sample
- **On the shelf / 本日上架**, the source registry and RSS shelf

## Architecture

```text
intake/sources.md
    -> canonical hand-maintained source registry
    -> controls On the shelf / 本日上架

intake/build.py
    -> parses sources.md
    -> generates feeds.yml
    -> fetches RSS items
    -> assembles index.html and gpt.md

intake/scripts/daily_postcard.py
    -> generates the daily postcard fragment

intake/scripts/daily_field_sample.py
    -> generates the Daily Field Sample fragment

intake/feeds.yml
    -> generated intermediate file; the committed copy also supplies base configuration

intake/index.html
    -> generated public page

intake/gpt.md
    -> generated by build.py
    -> renamed to llm-context.md by GitHub Actions

intake/llm-context.md
    -> generated reading context for AI; not hand-maintained
```

## Files

```text
intake/
├── README.md
├── sources.md
├── feeds.yml
├── requirements.txt
├── build.py
├── index.html
├── llm-context.md
├── scripts/
│   ├── daily_postcard.py
│   └── daily_field_sample.py
└── data/                         generated during a build, not committed by Actions
    ├── daily_postcard.html
    ├── daily_postcard.json
    ├── daily_field_sample.html
    └── daily_field_sample.json
```

`gpt.md` exists between the build and rename steps; the repository-facing output is [llm-context.md](https://github.com/fivsevn-agy/fivsevn-devlog/blob/main/intake/llm-context.md).

## Source registry

Edit [intake/sources.md](https://github.com/fivsevn-agy/fivsevn-devlog/blob/main/intake/sources.md) to change **On the shelf / 本日上架** sources, RSS URLs, and per-source fetch counts.

Each source uses this shape inside a fenced `source` block, not an ordinary `yaml` block. Preserve the surrounding category, display and section definitions already in `sources.md`.

```source
name: Example Source
section: science_news
feed_url: https://example.com/feed.xml
source_cap: 6
site_url: https://example.com/
source_type: specialist_media
authority_level: specialist
reliability_score: 4
professional_value: 4
use_role: baseline
```

If a source has no usable feed, keep it as a website source; change these fields in its existing source block:

```yaml
feed_url: ''
source_cap: 0
site_url: https://example.com/
```

## Spec reference

Field meanings and enum values are defined in `fivsevn-spec`:

- [Source Intake Fields](https://github.com/fivsevn-agy/fivsevn-spec/blob/main/source/spec-source-intake-fields-001.md)
- [Source Intake Enums](https://github.com/fivsevn-agy/fivsevn-spec/blob/main/appendix/spec-source-intake-enums-001.md)

`intake/sources.md` is the current selected source list. `fivsevn-spec` keeps the stable field rules and enum reference.

## Generated files

Do not hand-edit these as source files:

```text
intake/feeds.yml
intake/index.html
intake/gpt.md
intake/llm-context.md
intake/data/daily_postcard.html
intake/data/daily_postcard.json
intake/data/daily_field_sample.html
intake/data/daily_field_sample.json
```

They are generated by scripts and may be overwritten. The current workflow commits `index.html` and `llm-context.md`; it does not commit the regenerated `feeds.yml` or `data/`. Do not use the committed `feeds.yml` as a fresh export of the source registry.

## Manual build

From the repository root:

```bash
pip install -r intake/requirements.txt
python intake/scripts/daily_postcard.py
python intake/scripts/daily_field_sample.py
python intake/build.py
mv intake/gpt.md intake/llm-context.md
```

The final rename matches the Actions output. Running `build.py` alone leaves the AI context at `gpt.md`; it does not update `llm-context.md` by itself.

## GitHub Actions

The page is generated by [Build Intake Page](https://github.com/fivsevn-agy/fivsevn-devlog/actions/workflows/build-news.yml); configuration: [.github/workflows/build-news.yml](https://github.com/fivsevn-agy/fivsevn-devlog/blob/main/.github/workflows/build-news.yml).

- **Schedule**: `0 */5 * * *`, five planned runs per day at 00:00, 05:00, 10:00, 15:00 and 20:00 UTC. Actual runs can be delayed.
- **After editing sources**: a push to `main` changing `sources.md`, intake Python helpers, requirements, or this workflow triggers generation. Scheduled and manual runs remain available. Generated-only commits do not trigger another intake build.
- **Build order**: offline integrity tests → daily postcard → Daily Field Sample → `build.py` → rename `gpt.md` to `llm-context.md` → commit generated outputs. If the branch changes during generation, the job fails instead of publishing an obsolete result; rerun from the new head.
- **Storage**: `data/` is temporary build output; the workflow removes `data/` and the temporary `gpt.md` from Git tracking.
- **Verification**: check the build result, Pages deployment, and the actual page. A generated-file commit is not by itself proof that the website is current.

## Editing boundary

```text
Change On the shelf sources, RSS URLs, or per-source fetch counts
-> edit intake/sources.md

Change page structure, HTML assembly, header/footer, or rendering logic
-> edit intake/build.py

Change the postcard module
-> edit intake/scripts/daily_postcard.py

Change the Daily Field Sample module
-> edit intake/scripts/daily_field_sample.py
```

`intake/` is a current-facing generated page, not a permanent archive or canonical content axis. Published reading notes belong in posts, natsci or netcom.

## Source quality and integrity

Keep valuable websites even when articles cannot or must not be fetched. `manual` records represent owned-device documentation and are retained. The two-level catalog, mixed website/article shelf, per-source limits, typography, CSS and navigation remain the established presentation.

R assesses factual reliability within a stated domain; P assesses professional usefulness in the selected section. Neither is assigned mechanically from source type. The [shared field specification](https://github.com/fivsevn-agy/fivsevn-spec/blob/main/source/spec-source-intake-fields-001.md) defines evidence, scope, limitations and the optional `review` record. Existing scores without a review are historical assessments, not newly verified ratings. The existing R/P metadata row exposes the review in its tooltip; the LLM context carries the same reasons.

- `item_quality.py`: shared text/date normalization and conservative URL deduplication.
- `source_validation.py`: field, enum, URL, section and review-record checks.
- `audit_sources.py`: read-only audit and named review queue; it never changes ratings.
- `tests/test_intake.py`: offline feed fixtures, source-retention cases, deduplication and full-registry HTML/context parity.

```bash
python -m unittest discover -s tests -v
python intake/audit_sources.py --output /tmp/intake-audit.json
# Check the paired spec change before merging the two pull requests:
python intake/audit_sources.py --spec-root ../fivsevn-spec --output /tmp/intake-audit.json
```

`Check Intake Integrity` runs on relevant pull requests and uploads the audit JSON. The local `--spec-root` check verifies code/spec enum parity; merge the paired spec update before future parity checks against spec/main. An audit with no structural errors is not a claim that every source has undergone editorial review.

Publication, update, fetch and generation times are distinct. Missing publication dates are displayed as unknown, including update-only Atom entries. Website links have no publication date; their existing shelf ordering uses observation time. HTML and context receive one common generation timestamp. Feed requests have connect/read timeouts and failures keep the website entry.

Only known tracking parameters are ignored for article identity. Necessary and unknown URL parameters, fragments, trailing slashes and protocol differences are retained. Same titles or different-domain syndicated stories are not merged without stronger identity evidence. Duplicate articles within a placement collapse; all source/category/region provenance, original URLs and per-source ratings remain recorded. A cross-category article stays available in each category. Website cards are not merged with articles. Title and summary text is normalized once, then escaped for its output format; URLs are never passed through prose cleanup.
